# 요구사항 리뷰 체크리스트 (SWE.1)

| ID | 점검 항목 |
|----|-----------|
| REQ-01 | 모든 요구사항에 고유 ID(`SWR-FUN/QUA/LIM/CON-nnn`)가 있고 중복이 없다. |
| REQ-02 | 각 요구사항이 기능/품질/제한/제약 중 정확히 하나로 분류되어 있고 분류가 맞다. |
| REQ-03 | 기능 안전 요구사항(`FSR`)은 `docs/safety/`의 별도 문서에서 관리되고, 일반 요구사항 문서에 섞여 있지 않다(참조만 한다). |
| REQ-04 | 품질 요구사항은 ISO 25010 특성/부특성을 명시하고, 프로젝트가 지정한 판의 명칭을 쓴다. |
| REQ-05 | 품질·제한 요구사항에 측정 가능한 기준(수치, 조건, 측정 방법)이 있다. "빠르게", "충분히" 같은 모호한 표현이 없다. |
| REQ-06 | 각 요구사항이 한 가지만 말한다(원자성). 하나의 문장에 여러 요구가 섞여 있지 않다. |
| REQ-07 | 각 요구사항이 모호하지 않게 하나로 해석되며 "shall" 형식으로 작성되어 있다. |
| REQ-08 | 각 요구사항에 검증 방법과 수락 기준이 있고, 판정 가능하다. |
| REQ-09 | 요구사항 사이에 충돌·중복이 없다. |
| REQ-10 | 요구사항이 해결책(설계·구현 방법)을 지정하지 않는다. 지정한다면 제약(`CON`)으로 분류되고 근거가 있다. |
| REQ-11 | 상위 근거(시스템/이해관계자 요구)로의 상향 추적성이 있고, 근거 없는 요구사항이 없다. |
| REQ-12 | 이후 산출물(아키텍처 등)로의 하향 추적성이 `links.csv`에 있고 `check_traceability.py`가 통과한다. 하향 연결이 없는 요구사항이 없다. |
| REQ-13 | 요구사항 우선순위와 상태(초안/검토됨/승인됨)가 기록되어 있다. |
| REQ-14 | 외부 인터페이스(사용자, 하드웨어, 다른 시스템)에 대한 요구사항이 빠짐없이 있다. |
| REQ-15 | 오류·예외·경계 조건에 대한 요구사항이 정의되어 있다. |
| REQ-16 | 요구사항 변경이 있었다면 영향받는 하위 산출물과 추적성이 함께 갱신되었다. |
