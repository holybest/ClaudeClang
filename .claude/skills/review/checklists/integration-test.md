# 통합 테스트 리뷰 체크리스트 (SWE.5)

| ID | 점검 항목 |
|----|-----------|
| IT-01 | [설계 점검, CI 게이트 아님] 아키텍처의 모든 인터페이스(`IF`)와 그 함수·상태 코드·정의된 호출 순서가 인터페이스 커버리지 표(IF × 함수 × 상태 코드 × 테스트 ID)에 있고, 빈 칸이 없다. |
| IT-02 | 테스트가 모듈 내부가 아니라 컴포넌트 간 연동(인터페이스)을 검증한다. 모듈 내부 분기를 채우기 위한 테스트가 없다. |
| IT-03 | 통합 대상 컴포넌트끼리 실제 구현을 연결해서 테스트한다. 통합 대상 컴포넌트를 mock으로 대체한 테스트가 없다. |
| IT-04 | Stub/Mock이 제어할 수 없는 경계(하드웨어, 네트워크, 시간, 외부 시스템)나 필요한 오류·타임아웃 주입에만 쓰였다. |
| IT-05 | 인터페이스 계약 위반(사전 조건 위반, 범위 밖 값, null)에 대한 오류 코드 반환이 검증되었다. |
| IT-06 | 호출 순서·상태 관련 케이스(초기화 전 호출, 중복 호출, 재진입)가 있다. |
| IT-07 | 하위 컴포넌트 오류의 상위 전파와 처리가 검증되었다. |
| IT-08 | 아키텍처의 동적 시나리오(핵심 호출 순서)가 End-to-End로 실행되었다. |
| IT-09 | 시간·자원 제약(타임아웃, 버퍼 크기, 스레드)이 정의된 인터페이스는 그 제약이 검증되었다. |
| IT-10 | 동치 클래스 분할과 경계값 분석이 인터페이스 입력에 적용되었다. |
| IT-11 | 조합이 의미 있는 곳에 PICT가 사용되었고 모델 파일과 제외한 조합의 사유가 남아 있다. 사용하지 않았다면 사유가 있다. |
| IT-12 | 모든 테스트 함수에 Doxygen 주석으로 테스트 목적, 입력값, 절차, 예상 출력값이 있다. |
| IT-13 | 기대값이 아키텍처의 인터페이스 정의에서 도출되었다. |
| IT-14 | CLAUDE.md 2.1절의 통합 목표(**함수 커버리지 100 %, 성공률 100 %**)를 달성했고, 실제 측정 결과(`ci/scripts/coverage.sh integration` 출력)가 첨부·인용되어 있다. 목표 미달이면 사유와 승인이 있다. |
| IT-15 | 커버리지만을 위한 무의미한 테스트가 없다(단언 없음, 항상 참, 반환값 무시). |
| IT-16 | 테스트가 독립적이고 결정적이며 CTest(`integration` 라벨)에 등록되어 전부 통과한다. |
| IT-17 | 테스트 ID(`IT-nnn`)가 있고 `links.csv`에 `IF → IT`(및 `ARC → IT`, `SWR → IT`) 링크가 있다. `check_traceability.py --until test`가 통과한다. |
