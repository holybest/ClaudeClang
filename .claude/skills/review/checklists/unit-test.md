# 단위 테스트 리뷰 체크리스트 (SWE.4)

| ID | 점검 항목 |
|----|-----------|
| UT-01 | 설계 명세(`DD`)의 모든 공개 함수와 모든 반환 상태 코드에 대한 테스트가 있다. |
| UT-02 | 각 테스트 케이스의 기대값이 설계 명세에서 도출되었다(현재 코드 동작을 그대로 기록한 것이 아니다). |
| UT-03 | 모든 테스트 함수에 Doxygen 주석으로 테스트 목적, 입력값, 절차, 예상 출력값이 있다. |
| UT-04 | 동치 클래스 분할이 입력마다 수행되어 유효/무효 클래스 대표값이 다뤄졌다. |
| UT-05 | 경계값 분석(`min-1, min, min+1, max-1, max, max+1`, 0, 빈 입력, null)이 적용되었다. |
| UT-06 | 입력이 둘 이상이고 상호작용이 있는 함수에 PICT 조합이 사용되었고, 모델 파일과 제외한 조합의 사유가 남아 있다. 사용하지 않았다면 사유가 있다. |
| UT-07 | CLAUDE.md 2.1절의 단위 목표(**MC/DC 100 %, 분기 100 %, 성공률 100 %**)를 달성했다. 실제 측정 결과(`ci/scripts/coverage.sh unit` 또는 `coverage.sh --mcdc --mcdc-target 100 --branch 100` 출력)가 첨부·인용되어 있다. 목표 미달이면 사유와 승인이 있다. |
| UT-08 | MC/DC 목표가 있는 경우 LLVM 도구(`coverage.sh --mcdc`)로 측정했고, 모든 조건의 독립 쌍이 커버되었다. |
| UT-09 | 커버리지만을 위한 무의미한 테스트가 없다: 모든 테스트가 의미 있는 단언을 가지며, 단언이 없거나 항상 참이거나 반환값을 무시하는 테스트가 없다. |
| UT-10 | Stub/Mock이 필요한 곳(제어 불가능한 외부 의존, 다른 모듈의 `IF` 격리)에만 쓰였고, 대상 모듈 내부 함수를 mock하지 않으며, mock 호출 검증에만 의존하는 테스트가 없다. |
| UT-11 | 테스트가 독립적이고 결정적이다(실행 순서·시간·외부 상태·난수에 의존하지 않는다). |
| UT-12 | 테스트가 CTest에 등록되어 있고 전부 통과한다. 비활성화·건너뛴 테스트가 없다(있다면 사유). |
| UT-13 | 오류 경로와 상태 전이(초기화 전 호출, 중복 호출 등)가 다뤄졌다. |
| UT-14 | 테스트 ID(`UT-nnn`)가 있고 `links.csv`에 `DD → UT`(및 직접 검증하는 `SWR → UT`) 링크가 있다. `check_traceability.py --until test`가 통과한다. |
| UT-15 | 실패 시 원인을 알 수 있는 이름과 메시지를 쓴다(`<대상>_<동작>_<조건>`). |
| UT-16 | 단위 커버리지가 `tests/unit/`(라벨 `unit`) 테스트만으로 측정되었다. TDD 테스트(`tests/tdd/`)를 합산하지 않았다. |
