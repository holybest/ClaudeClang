# 상세 설계 리뷰 체크리스트 (SWE.3)

| ID | 점검 항목 |
|----|-----------|
| DD-01 | 모든 모듈에 고유 ID(`DD-nnn`), 소속 `ARC`, 한 문장 책임, 소스 파일이 있다. |
| DD-02 | 모든 `ARC`가 하나 이상의 `DD`로 분해되어 있고, 소속 `ARC` 없는 `DD`가 없다. (`check_traceability.py --until design`) |
| DD-03 | 인터페이스 정의 기준(다른 모듈이 호출하는 공개 함수, 컴포넌트 간 데이터 교환, 공개 함수 3개 초과 또는 상태 보유)에 해당하는 모든 모듈이 인터페이스를 정의한다. 정의하지 않은 모듈에는 사유가 적혀 있다. |
| DD-04 | 인터페이스가 있는 모듈은 오직 그 인터페이스로만 다른 모듈과 통신하고, 인터페이스에 없는 함수·타입·전역 변수를 외부에 노출하지 않는다. |
| DD-05 | 모듈의 인터페이스가 아키텍처의 `IF` 정의와 일치한다(시그니처, 오류 코드, 사전/사후 조건). |
| DD-06 | 단일 책임: 모듈과 함수가 각각 한 가지 변경 이유만 갖는다. |
| DD-07 | 클린 코드: 이름이 의도를 드러내고, 함수가 짧고 한 가지 추상화 수준을 유지하며, 인자가 많지 않고, 중복·매직 넘버가 없다. |
| DD-08 | 모든 공개 함수에 입력/출력, 반환 상태 코드, 사전/사후 조건이 정의되어 있다. |
| DD-09 | 모든 함수가 반환값(없으면 상태 코드)을 가지며, 의사코드가 "마지막에 한 번만 return" 형태이다. |
| DD-10 | 동작(알고리즘, 제어 흐름, 상태 전이)이 구현할 수 있을 만큼 구체적이고, 요구사항·아키텍처와 모순되지 않는다. |
| DD-11 | 오류 처리와 경계 조건(null, 범위 밖, 자원 부족, 초기화 전 호출)이 정의되어 있다. |
| DD-12 | 내부 데이터의 타입·불변식·소유권이 정의되어 있다. |
| DD-13 | 모듈 간 순환 의존이 없고, 의존이 인터페이스(`IF`)만 사용한다. |
| DD-14 | 설계 결정의 근거와 검토한 대안이 기록되어 있다. |
| DD-15 | 제한(`SWR-LIM`)을 만족하는 설계다(시간, 메모리 등 예산 내에서 동작). |
| DD-16 | 각 모듈이 단위 시험 가능하도록 의존성이 분리되어 있다(주입 가능한 인터페이스 등). |
