# 아키텍처 리뷰 체크리스트 (SWE.2)

| ID | 점검 항목 |
|----|-----------|
| ARC-01 | 모든 컴포넌트에 고유 ID(`ARC-nnn`), 이름, 한 문장 책임이 있다. |
| ARC-02 | 모든 `SWR`이 하나 이상의 컴포넌트에 할당되어 있고, 요구사항 없는 컴포넌트가 없다. (`check_traceability.py --until arch`) |
| ARC-03 | 모든 컴포넌트가 하나 이상의 인터페이스(`IF-nnn`)를 가진다. |
| ARC-04 | 각 인터페이스에 제공자/사용자, 시그니처, 입출력(타입·단위·범위·소유권), 사전/사후 조건, 오류 처리, 호출 순서·시간 제약이 정의되어 있다. |
| ARC-05 | 컴포넌트 간 의존이 오직 인터페이스를 통해서만 존재한다. 다른 컴포넌트의 내부 타입·헤더·전역 변수에 대한 직접 의존이 없다. |
| ARC-06 | 컴포넌트 간 순환 의존이 없다. |
| ARC-07 | 응집도가 높다: 각 컴포넌트가 한 가지 이유로만 변경된다. 책임 설명에 "그리고/및"이 들어간 컴포넌트가 없다. |
| ARC-08 | 결합도가 낮다: 컴포넌트당 사용하는 인터페이스 수가 과도하지 않고, 공통 데이터·전역 상태 공유가 없다. |
| ARC-09 | 내부 구현이 캡슐화되어 있고 인터페이스로 필요한 것만 노출한다. |
| ARC-10 | SOLID: 단일 책임, 개방-폐쇄, 리스코프 치환, 인터페이스 분리(비대한 인터페이스가 없음), 의존성 역전(상위 정책이 세부 구현이 아니라 추상에 의존)을 위반하지 않는다. 위반한 결정은 근거가 기록되어 있다. |
| ARC-11 | 주요 설계 결정에 근거와 검토한 대안이 기록되어 있다. |
| ARC-12 | 동적 동작(핵심 시나리오의 호출 순서, 필요 시 상태 전이)이 정의되어 있다. |
| ARC-13 | 품질 요구사항(`SWR-QUA`)과 제한(`SWR-LIM`)이 아키텍처 결정에 반영되어 있다(자원 소비 목표 포함). |
| ARC-14 | 제약(`SWR-CON`)을 위반하는 설계 결정이 없다. |
| ARC-15 | 기능 안전 요구사항(`FSR`)의 할당이 필요하면 별도 문서와 일관되게 반영되어 있다. |
| ARC-16 | 컴포넌트 → 상세 설계(`DD`) 분해 방향이 가능하도록 컴포넌트 경계가 충분히 구체적이다. |
| ARC-17 | 다이어그램과 본문(컴포넌트 목록·인터페이스 표)이 서로 일치한다. |
