# 상세 설계 (A-SPICE SWE.3)

입력은 검토된 아키텍처 `docs/architecture/`이다. 산출물은 `docs/design/`에 둔다.
아키텍처가 없으면 `/architecture-design`을 먼저 하도록 안내한다.

## 규칙

1. **모듈 정의**: 각 컴포넌트(`ARC`)를 모듈(`DD-nnn`)로 분해한다. 모듈은 이름, 책임(한 문장), 소속 `ARC`, 소스 파일, 공개 함수, 내부 데이터, 알고리즘/제어 흐름을 가진다.
2. **인터페이스 정의 기준 ("특정 수준")**: 아래 중 하나라도 해당하면 그 모듈은 인터페이스를 **반드시** 정의한다.
   - 다른 모듈이 호출하는 공개 함수가 있다.
   - 다른 컴포넌트와 데이터를 주고받는다.
   - 공개 함수가 3개를 넘거나 상태(내부 데이터)를 가진다.

   기준 값은 CLAUDE.md의 "A-SPICE 개발 프로세스" 절에 정의된 값이 있으면 그것을 따른다.
   해당하지 않는 작은 모듈(순수 보조 함수 묶음 등)은 인터페이스 없이 두되, 그 이유를 한 줄로 적는다.
3. **인터페이스 전용 통신**: 인터페이스가 정의된 모듈은 다른 모듈과 오직 그 인터페이스로만 통신한다. 인터페이스에 없는 함수·타입·전역 변수는 모듈 외부에 노출하지 않는다.
   (C++: 인터페이스는 순수 가상 클래스/컨셉, 구현은 `.cpp`와 익명 네임스페이스에 둔다. C: 공개 헤더와 `static` 내부 함수를 분리한다.)
4. **클린 코드**: 의미 있는 이름, 짧은 함수(권장 20줄 이하, 인자 3개 이하), 한 가지 추상화 수준, 부수효과 최소화, 중복 제거(DRY), 주석 대신 코드로 의도를 표현, 매직 넘버 금지.
5. **단일 책임 원칙**: 모듈과 함수 모두 변경 이유가 하나여야 한다. 책임 설명에 "그리고/및"이 들어가면 분리한다.
6. **반환값 규칙**: 모든 함수는 값을 반환하고(반환할 값이 없으면 상태 코드), 마지막에 return이 한 번만 오도록 설계한다. 의사코드도 이 형태로 쓴다. 구현 스킬이 같은 규칙을 코드에 적용한다.

## 산출물 형식

`docs/design/<컴포넌트>.md`
```markdown
### DD-nnn <모듈 이름>
- 소속: ARC-nnn
- 책임: <한 문장>
- 소스: src/<경로>, include/<경로>
- 인터페이스: IF-nnn  (또는 "없음 – 사유: ...")
- 공개 함수: 시그니처, 입력/출력, 반환 상태 코드, 사전/사후 조건
- 내부 데이터: 이름, 타입, 불변식
- 동작: 의사코드 또는 순서도(복잡한 경우 상태 전이)
- 의존: 사용하는 IF-nnn
- 설계 결정: 근거와 검토한 대안
```

## 추적성

- `ARC → DD` 링크를 `docs/traceability/links.csv`에 추가한다. 모든 `ARC`는 하나 이상의 `DD`를 가지고, 모든 `DD`는 `ARC`에 속한다.
- 검사: `python -I .claude/skills/requirements-analysis/scripts/check_traceability.py --until design`

## 완료 조건

1. 모든 모듈이 한 가지 책임을 가진다.
2. 인터페이스 기준에 해당하는 모듈은 모두 인터페이스가 정의되어 있고, 모듈 간 의존이 인터페이스만 사용한다.
3. 추적성 검사(`--until design`)가 통과한다.
4. `/review detailed-design`으로 리뷰하고 결과를 `docs/reviews/`에 남긴다.
