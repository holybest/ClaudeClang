# 통합 테스트 (A-SPICE SWE.5)

입력은 아키텍처(`docs/architecture/`)와 구현된 컴포넌트이다. 테스트는 `tests/integration/`에 두고 CTest에 `integration` 라벨로 등록한다.
단위 테스트(`/unit-test`)가 끝난 모듈을 대상으로 한다.

## 1. 범위: 인터페이스 중심

통합 테스트의 대상은 모듈 내부가 아니라 **컴포넌트 간 연동**이다. 아키텍처의 인터페이스(`IF-nnn`)마다 다음을 검증한다.

- 정상 호출: 제공자·사용자가 실제로 연결되어 데이터와 상태 코드가 계약대로 오가는가 (타입·단위·범위·소유권)
- 인터페이스 계약 위반: 사전 조건 위반 입력, 범위 밖 값, null에 대해 정의된 오류 코드를 반환하는가
- 호출 순서·상태: 인터페이스에 정의된 호출 순서, 초기화 전 호출, 중복 호출, 재진입
- 오류 전파: 하위 컴포넌트가 오류를 반환했을 때 상위로 올바르게 전파·처리되는가
- 시간·자원 제약: 인터페이스에 명시된 타임아웃, 버퍼 크기, 스레드 제약
- 아키텍처의 동적 시나리오(핵심 호출 순서)를 끝에서 끝까지 한 번씩 실행

모듈 내부 분기를 채우려는 테스트는 단위 테스트의 몫이다. 통합 테스트에 넣지 않는다.

## 2. 커버리지 목표

- 목표는 CLAUDE.md의 "A-SPICE 개발 프로세스" 절 `커버리지 목표`를 따른다. **통합 시험 목표가 정의되어 있지 않으면 사용자에게 묻는다.** (기본 제안: 모든 `IF`의 모든 함수·상태 코드·정의된 호출 순서를 100 % 다룬다. 인터페이스 커버리지)
- 인터페이스 커버리지는 `docs/design`·`docs/architecture`의 인터페이스 표와 테스트의 `@trace`를 대조해 만든 표(`IF` × 함수 × 상태 코드 × 테스트 ID)로 확인한다. 빈 칸이 없어야 한다.
- 코드 커버리지 목표도 정해져 있으면 `bash .claude/skills/unit-test/scripts/coverage.sh --label integration`으로 측정한다. (MC/DC 등 옵션은 unit-test 스킬 참조)
- 목표를 **100 % 달성할 때까지** 측정 → 미커버 분석 → 케이스 추가를 반복하고, 반복마다 수치를 보고한다.

## 3. 테스트 케이스 설계

단위 테스트와 같은 기법을 인터페이스 입력에 적용한다. (자세한 절차와 PICT 모델 예시는 `.claude/skills/unit-test/SKILL.md`, `.claude/skills/unit-test/templates/` 참조)

1. **동치 클래스 + 경계값 분석**: 인터페이스 인자·메시지 필드마다 클래스와 경계값을 도출한다.
2. **PICT 조합**: 인터페이스 인자, 컴포넌트 상태(초기화 여부, 모드), 하위 컴포넌트 응답(정상/오류/타임아웃) 등을 파라미터로 하여 조합을 생성한다.
3. 기대값은 아키텍처의 인터페이스 정의(사전/사후 조건, 오류 처리)에서 도출한다.

## 4. 작성 규칙

- **의미 없는 테스트 금지**: 커버리지나 표의 빈 칸을 채우기 위한 무의미한 케이스(단언 없음, 항상 참인 단언)를 넣지 않는다.
- **Stub/Mock은 필요한 경우에만**: 하드웨어, 네트워크, 시간, 통합 대상 밖의 외부 시스템처럼 제어할 수 없는 경계에만 쓴다. **통합 대상 컴포넌트끼리는 실제 구현을 연결**한다. 통합 대상 컴포넌트를 mock으로 대체하면 통합 테스트가 아니다. 오류·타임아웃 주입이 꼭 필요한 하위 컴포넌트만 해당 `IF`의 test double로 대체한다.
- **Doxygen 주석 필수**: 모든 테스트 함수에 목적, 입력값, 절차, 예상 출력값을 적는다. 형식은 `.claude/skills/unit-test/templates/test_example.cpp`와 같고, `@trace`는 `IT-nnn -> IF-nnn, ARC-nnn (SWR-…)` 형태로 쓴다.
- 테스트는 독립적이고 결정적이어야 한다. 이름은 `<IF>_<동작>_<조건>` 형태로 쓴다.

## 5. 절차 요약

1. 인터페이스 목록(`IF`)과 인터페이스 커버리지 표 작성, 커버리지 목표 확인
2. 인터페이스별 케이스 설계 (동치 클래스 → 경계값 → PICT)
3. 테스트 작성 + Doxygen 주석 → `/build`, `/test`
4. 인터페이스 커버리지 표(와 코드 커버리지) 확인 → 미달 항목 분석 → 케이스 추가 → 목표 달성까지 반복
5. `links.csv`에 `IF-nnn,IT-nnn` (필요하면 `ARC-nnn,IT-nnn`, `SWR-…,IT-nnn`) 링크 추가
6. `python -I .claude/skills/requirements-analysis/scripts/check_traceability.py --until test`
7. `/review integration-test`로 리뷰하고 결과를 `docs/reviews/`에 남긴다.
